# Сопроводительная документация

## 1. Постановка задачи

Разработано браузерное приложение для интерактивной работы с цветовыми моделями по варианту 9:

```text
HSV ↔ XYZ ↔ LAB
```

Пользователь может изменить цвет ползунками, ввести точные координаты или выбрать цвет из системной палитры. После изменения любой координаты все остальные представления обновляются автоматически.

Все математические операции реализованы вручную на JavaScript. Внешние библиотеки цветовых преобразований не используются.

## 2. Диапазоны компонентов

| Модель | Компонента | Диапазон в интерфейсе |
| --- | --- | ---: |
| HSV | H — цветовой тон | 0…360° |
| HSV | S — насыщенность | 0…100% |
| HSV | V — яркость | 0…100% |
| XYZ | X | 0…100 |
| XYZ | Y | 0…100 |
| XYZ | Z | 0…110 |
| LAB | L — светлота | 0…100 |
| LAB | a — зелёный/красный | −128…127 |
| LAB | b — синий/жёлтый | −128…127 |

Внутри вычислений сохраняются дробные значения. Округление применяется только при выводе координат пользователю.

## 3. Общая цепочка преобразований

Для отображения цвета браузеру нужны компоненты sRGB, поэтому RGB применяется как внутреннее промежуточное представление:

```text
HSV ↔ sRGB ↔ XYZ ↔ LAB
```

Если источником изменения является XYZ или LAB, соответствующие исходные координаты сохраняются. Коррекция диапазона применяется только к полученному sRGB, необходимому для HSV и экранного образца.

## 4. Преобразование HSV ↔ RGB

Для HSV → RGB сначала нормализуются насыщенность и яркость:

```text
s = S / 100
v = V / 100
C = v · s
X = C · (1 − |(H / 60 mod 2) − 1|)
m = v − C
```

В зависимости от сектора цветового круга выбирается одна из комбинаций `(C, X, 0)`. Затем к каждой компоненте прибавляется `m`, и значения умножаются на 255.

Для RGB → HSV используются:

```text
max = max(r, g, b)
min = min(r, g, b)
Δ = max − min
V = max
S = 0, если max = 0; иначе Δ / max
```

Цветовой тон вычисляется по компоненте, в которой находится максимум, после чего приводится к диапазону 0…360°.

## 5. Гамма-коррекция sRGB

Перед умножением на матрицу нелинейная компонента sRGB переводится в линейную:

```text
c_lin = c / 12.92,                         если c ≤ 0.04045
c_lin = ((c + 0.055) / 1.055) ^ 2.4,      иначе
```

Обратная функция:

```text
c = 12.92 · c_lin,                         если c_lin ≤ 0.0031308
c = 1.055 · c_lin ^ (1 / 2.4) − 0.055,    иначе
```

Здесь `c` находится в диапазоне 0…1.

## 6. Динамическое построение матриц RGB ↔ XYZ

В программе отсутствуют готовые матрицы преобразования. Они строятся заново из координат первичных цветов sRGB и выбранной белой точки.

### 6.1. Исходные координаты

| Точка | x | y |
| --- | ---: | ---: |
| R | 0.64000 | 0.33000 |
| G | 0.30000 | 0.60000 |
| B | 0.15000 | 0.06000 |
| D65 | 0.31270 | 0.32900 |
| D50 | 0.34567 | 0.35850 |
| E | 1/3 | 1/3 |

Координаты первичных цветов и белых точек являются исходными справочными данными, а не готовыми коэффициентами преобразования.

### 6.2. Алгоритм построения

Координаты цветности `(x, y)` переводятся в XYZ при `Y = 1`:

```text
X = x / y
Y = 1
Z = (1 − x − y) / y
```

Из столбцов первичных цветов составляется матрица:

```text
P = [Rxyz Gxyz Bxyz]
```

Аналогично рассчитывается вектор выбранной белой точки `W`. Масштабы первичных цветов находятся решением системы:

```text
S = P⁻¹ · W
```

Итоговая матрица строится во время выполнения программы:

```text
M_RGB→XYZ = P · diag(S)
M_XYZ→RGB = M_RGB→XYZ⁻¹
```

При выборе D65, D50 или E функция выполняется снова, поэтому обе матрицы и белая точка LAB автоматически меняются.

Для удобства отображения компоненты XYZ после умножения масштабируются в диапазон 0…100.

## 7. Преобразование XYZ ↔ LAB

Используется белая точка текущего источника освещения `(Xn, Yn, Zn)` и функция:

```text
δ = 6 / 29

f(t) = ∛t,                    если t > δ³
f(t) = t / (3δ²) + 4 / 29,   иначе
```

Прямое преобразование:

```text
L = 116 · f(Y / Yn) − 16
a = 500 · (f(X / Xn) − f(Y / Yn))
b = 200 · (f(Y / Yn) − f(Z / Zn))
```

Обратное преобразование сначала восстанавливает:

```text
fy = (L + 16) / 116
fx = fy + a / 500
fz = fy − b / 200
```

Затем применяется обратная кусочная функция:

```text
f⁻¹(t) = t³,                         если t > δ
f⁻¹(t) = 3δ² · (t − 4 / 29),        иначе
```

Полученные отношения умножаются на текущую белую точку.

## 8. Обработка выхода за диапазон sRGB

Исходный XYZ или LAB может описывать цвет, который невозможно показать средствами sRGB. Пользователь выбирает одну из двух стратегий.

### Clipping

Каждая компонента ограничивается независимо:

```text
c' = min(255, max(0, c))
```

Например, `RGB(−12, 128, 270)` превращается в `RGB(0, 128, 255)`.

### Scaling

Для трёх компонентов выбираются общие границы:

```text
lower = min(0, R, G, B)
upper = max(255, R, G, B)
c' = 255 · (c − lower) / (upper − lower)
```

Таким образом весь набор компонентов одной линейной функцией помещается в диапазон 0…255. При применении любой стратегии интерфейс показывает предупреждение.

## 9. Автоматический пересчёт

Программа хранит активную модель — ту, которую пользователь изменил последней.

1. Считываются три координаты активной модели.
2. Они переводятся в остальные модели по общей цепочке.
3. При необходимости полученный RGB корректируется выбранной стратегией.
4. Обновляются числовые поля, положения ползунков, HEX-код и образец цвета.
5. Перестраиваются динамические градиенты.

Программное присваивание значений полям не создаёт новых событий браузера, поэтому циклического пересчёта не возникает.

## 10. Динамические градиенты

Для каждого ползунка вычисляется 13 цветовых точек. В каждой точке изменяется только компонента данного ползунка, а остальные сохраняют текущие значения.

Каждая точка переводится собственной математикой приложения в sRGB. Из результатов формируется CSS-градиент. Пересчёт выполняется при изменении:

- любого ползунка или числового поля;
- цвета в палитре;
- источника освещения;
- стратегии Clipping/Scaling.

Чтобы перемещение ползунка оставалось плавным, перестроение градиентов синхронизировано с кадрами браузера через `requestAnimationFrame`.

## 11. Проверка корректности

Автоматические тесты охватывают:

- определитель, умножение и обращение матриц 3×3;
- построение матриц для D65, D50 и E;
- совпадение рассчитанной D65-матрицы с эталонной sRGB-матрицей;
- красный, зелёный и синий цвета HSV;
- обратные переходы RGB → HSV → RGB;
- обратные переходы RGB → XYZ → RGB для трёх источников света;
- превращение белой точки в `LAB(100, 0, 0)`;
- обратные переходы XYZ → LAB → XYZ;
- полный путь HSV → XYZ → LAB → RGB → HSV;
- обе стратегии обработки диапазона;
- построение динамических градиентов без `NaN` и бесконечных значений.

Команда запуска проверок:

```bash
npm test
```

## 12. Запуск программы

Сборка и сервер не требуются. Файл `index.html` можно открыть напрямую в современном браузере. Опубликованная версия работает как статический сайт GitHub Pages.
